SECTION 12 - So sánh Comparable và Comparator
========================================================

Q1: Class nào nên implement Comparable interface?
A: Class Media nên implement Comparable<Media>, vì Media là superclass
   chung của tất cả các loại media (DVD, CD, Book). Khi đó tất cả
   các subclass đều kế thừa được thứ tự sắp xếp mặc định.

Q2: Cần implement compareTo() như thế nào để phản ánh đúng thứ tự sắp xếp?
A: Ví dụ với thứ tự sắp xếp theo title tăng dần, nếu cùng title thì
   theo cost giảm dần:

   public int compareTo(Media other) {
       int cmp = this.getTitle().compareTo(other.getTitle());
       if (cmp != 0) return cmp;
       return Float.compare(other.getCost(), this.getCost()); // giảm dần
   }

   Với thứ tự sắp xếp theo cost giảm dần, nếu cùng cost thì theo title:

   public int compareTo(Media other) {
       int cmp = Float.compare(other.getCost(), this.getCost()); // giảm dần
       if (cmp != 0) return cmp;
       return this.getTitle().compareTo(other.getTitle());
   }

Q3: Có thể có 2 thứ tự sắp xếp khác nhau khi dùng Comparable không?
A: Không. Comparable chỉ cho phép định nghĩa DUY NHẤT một thứ tự sắp
   xếp tự nhiên (natural ordering) thông qua phương thức compareTo().
   Nếu muốn có 2 kiểu sắp xếp khác nhau (theo title và theo cost),
   bắt buộc phải dùng Comparator vì có thể tạo nhiều class Comparator
   độc lập với nhau.

Q4: Giả sử DVD có thứ tự sắp xếp riêng (theo title, rồi length giảm dần,
    rồi cost). Cần sửa code như thế nào?
A: Nếu đang dùng Comparable thì KHÔNG THỂ xử lý được trường hợp này,
   vì compareTo() được định nghĩa trong Media và áp dụng chung cho
   tất cả subclass. DVD không thể có thứ tự riêng mà không ảnh hưởng
   đến Book và CD.

   Giải pháp: dùng Comparator. Tạo thêm một class riêng cho DVD:

   public class DVDComparatorByTitleLengthCost implements Comparator<Media> {
       public int compare(Media a, Media b) {
           // Bước 1: so sánh theo title tăng dần
           int cmp = a.getTitle().compareTo(b.getTitle());
           if (cmp != 0) return cmp;

           // Bước 2: so sánh theo length giảm dần
           DigitalVideoDisc da = (DigitalVideoDisc) a;
           DigitalVideoDisc db = (DigitalVideoDisc) b;
           cmp = Integer.compare(db.getLength(), da.getLength());
           if (cmp != 0) return cmp;

           // Bước 3: so sánh theo cost tăng dần
           return Float.compare(a.getCost(), b.getCost());
       }
   }

   Sau đó gọi:
   Collections.sort(danhSachDVD, new DVDComparatorByTitleLengthCost());

   Như vậy Book và CD vẫn dùng comparator riêng của chúng, không bị
   ảnh hưởng.

SECTION 11 - Đa hình với phương thức toString()
========================================================

Q: Quan sát điều gì xảy ra khi gọi toString() trên List<Media>? Giải thích.
A: Khi duyệt qua List<Media> và gọi m.toString(), Java tự động gọi
   đúng phiên bản toString() của class thực sự của object đó tại
   thời điểm chạy chương trình (runtime), không phải theo kiểu biến
   được khai báo (Media).

   Cụ thể:
   - Nếu object thực sự là CompactDisc  -> CompactDisc.toString() được gọi
   - Nếu object thực sự là DigitalVideoDisc -> DigitalVideoDisc.toString()
   - Nếu object thực sự là Book         -> Book.toString() được gọi

   Đây gọi là đa hình tại runtime (runtime polymorphism) hay dynamic
   dispatch. Java xác định phương thức nào được gọi dựa vào kiểu thực
   sự của object trong bộ nhớ, không phải kiểu của biến tham chiếu.
   Đây là một trong những tính chất quan trọng nhất của lập trình
   hướng đối tượng.
